## 4. 分阶段路线图（每阶段独立可验收、可发布）

### P2 · 恢复体面（对标竞品最硬卖点）
1. **导出**：把 ~/.dsh 打成单文件 ZIP（`dsh-config-<时间>.zip`），节段化（settings/UI/providers/plugins/MCP/skills/prompts/workspaces/sessions/credentials），默认脱敏、可选加密。
2. **导入**：`分析 → 预览 → 逐项/冲突选择（保留/采用，含批量）→ 自动快照 → 应用 → 校验 → 失败回滚`；跨机绝对路径 remap（批量前缀映射）；兼容性评分（source 版本/平台 → 本地，结构化原因）。
3. **加密**：可选口令 → scrypt 派生 + AES-256-GCM，随机 salt/IV，凭据仅以密文入包。
4. **验收**：smoke 场景 + e2e 全链路；加密包解密回读、密码错误拒绝、密文不回显不落日志。

### P3 · 同步/运维体面
1. 同步多通道：Git / WebDAV / S3 兼容（AWS S3、Aliyun OSS、Tencent COS、MinIO、Qiniu）/ GitHub Gist。
2. GFS 保留：最近 N + 每月一份 + 每年一份。
3. 操作锁 + 残留锁回收（心跳 + 死锁判定）。
4. 磁盘占用报告 + 分级清理（只清可再生缓存与过期备份，快照/同步数据不动）。
5. 定时备份自定义每周时刻。

### P4 · 生态体面
1. 配置市场（浏览 + dry-run 预览 + 供应链警告 + 逐段批准）。
2. 外部 agent 导入（Claude Code/Cursor/Codex…配置 + 聊天记录，先 3~5 源再扩）。
3. Profiles 管理 UI；4. 会话 Rewind；5. 本地 link:/file: 插件迁移；6. About 面板 + 环境信息 + 一键反馈；7. agent 工具扩到 5 个；8. 离线 CLI 补 reinstall / sessions repair / 锁回收。

## 5. 心理化设计 + 宣发原则（落地到文案/层级/物料）

1. **损失厌恶**：恢复入口反复强调「先自动快照、可回滚、不会静默覆盖」，把「恢复会不会毁掉我现有东西」这个最大恐惧前置化解。
2. **默认效应 + 实施意图**：自动备份给推荐值（12h/7 份），按钮文案是「开启自动备份」而非「配置定时任务」；引导第 3 步直接给行动，不留给用户计算。
3. **峰终定律**：备份完成那一刻给明确的「✅ 完成 + 文件在哪 + 怎么恢复」收尾（峰值）；面板底部永远是低声量反馈入口（终值友好）。
4. **社会证明**：README/面板放 `191★ 同类方案都在解决什么问题 → 我们更聚焦 X` 的对比，而非空泛「好用」。
5. **互惠**：先给用户可见价值（首启一键备份、免费）再请求 Star/反馈。
6. **降低认知负荷**：术语换成结果语言（「校验」→「检查备份是否完好」；「分类型备份」→「只备份选中的部分」）；信息密度分级（主 CTA > 状态 > 列表 > 高级折叠）。
7. **风险可视化**：危险动作（删除/恢复）用红/警告色 + 二次确认 + 可逆提示；加密口令缺失后果（口令即唯一钥匙）写进表单，不用小字藏。
8. **宣发钩子**（README/市场卡片）：一句话讲「怕升级翻车 / 换机丢配置」，三句讲「备份 / 恢复 / 自动备份」，一句安全承诺「凭据不离开本机，可再加密」。
